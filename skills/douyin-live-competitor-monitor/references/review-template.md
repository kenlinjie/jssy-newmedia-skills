# 复盘写作标准（`复盘.md`）

每场下播后写一份，存为该场目录下 `复盘.md`，**与邮件正文逐字一致**。网站优先展示它。

## 铁律

1. **不编造**。逐字稿/数据里没有的一律写「未获取」，绝不估算、绝不脑补。
2. **第三节必须来自逐字稿真实内容**，带原话或具体数字。写成"讲了政策、讲了择校"这种就是废稿。
3. **第四节要说人话**：没有留资动作就直接写「全场零表单、零二维码、零商品、零价格」。
4. 正文**不写**在线链接、不写本地路径、不用 emoji、不写 HTML。
5. 数字口径要标清是"达线"还是"录取"——竞品最常混用这两个词，混了就把口径差异误判成造假。

## 六节结构（顺序固定，标题不要改）

```markdown
# 竞品直播复盘｜<主播名>
（is_self=true 时写 # 自有号直播复盘｜<主播名>）

**主播**：<主播名>（抖音号 <号>） / **场次**：YYYY-MM-DD HH:MM – HH:MM（**N 分钟**） / **标题**：<直播标题>

## 一、整场数据

| 指标 | 数值 |
| --- | --- |
| 峰值在线 | N 人（HH:MM、HH:MM 两次触及） |
| 平均在线 | N 人 |
| 累计观看 | N 人 |
| 开播 / 收尾在线 | N 人 / N 人 |

## 二、在线人数走势

- 按时间顺序写关键时点，每行一个阶段，带具体人数
- 写清峰值出现在哪个时段、当时在讲什么
- 末尾一句结论，四选一：**稳定上扬 / 推流突发 / 一路下滑 / 窄幅波动**，并给依据
  （例："142 分钟里没有一分钟超过 13 人，峰值只比平均高 6.1 人"）

## 三、核心内容与卖点

1. 3-6 条，每条讲一件事，带具体数字/名额/分数线/原话
2. 优先选"能决策"的信息：名额、降分、费用、班型、录取路径
3. 排序：先全场骨架（头部校数据），再细节（入学路径、位次线），最后变量（渠道、口径变化）

## 四、引导话术与转化动作

- 引真实原话，标出现次数（例：「点关注」出现 87 次、「私信」17 次）
- 写清留资方式：私信留号码 / 截屏进群 / 后台 / 表单 / 商品链接
- 给出转化漏斗：累计观看 → 关注 → 留资 → 进群 → 到店 → 报名，每一环可计量就写数、不可计量就写"不可计数"
- 没有的动作直接指出"零表单、零二维码、零商品、零价格"

## 五、对我们的启示

2-3 条，是"我们能拿去用"的判断，不是复述竞品。
必须能落到动作：选题前置什么、钩子怎么配兑付、留资链路怎么补编号。

> is_self=true 时本节改为 **## 五、下次必须改的三点**，写我们自己这场的问题和改法。

## 六、合规说明

固定一段，原样照抄：

> 仅录制音频，不录视频、不抓弹幕；在线人数为平台接口真实采样，未做平滑或估算；逐字稿由离线模型转写，个别语句识别不准。
```

## 质量对照（同一场，差稿 vs 好稿）

| 位置 | 差稿 | 好稿 |
|---|---|---|
| 三、内容 | "介绍了各校录取情况和择校建议" | "清开给了可执行的位次线：大淮 127 人，前 130、140 可冲刺大淮，前 220、230 可把第一志愿给新淮；并披露生源 40%-50% 来自涟水" |
| 二、走势 | "人数有波动" | "18:42 开播只有 1 人，18:59 才到 6 人；19:30 首触峰值 13 人；19:50 起逐级下滑，20:32 掉到 4 人；收尾 5 人" |
| 四、话术 | "引导家长关注和进群" | "「点关注」87 次、「点赞」63 次，几乎每 3-4 分钟插一次，但主播自认没人应答：「妈不讲又没人了」" |
| 五、启示 | "要加强内容质量" | "142 分钟只做出 6.9 平均在线，'时长换流量'本身失效；峰值出现在讲天山四档收费（一档一年 1.2 万）那一段——家长对'小众路径+花多少钱'的反应强于对头部校达线人数的反应，选题应把决策题前置" |

## 写作前的数据准备

| 要写哪节 | 先看什么 |
|---|---|
| 一、数据 | `viewers.csv`（列序有坑，见 pitfalls.md）、`摘要.md` |
| 二、走势 | `viewers.csv` 全量，找出 max 那一行的时间 |
| 三、内容 | `transcript.txt` 全文 |
| 四、话术 | `transcript.txt` 里 grep「关注」「点赞」「私信」「后台」「群」「截图」「免费」「报名」「多少钱」 |
| 五、启示 | 结合第三节的卖点 + 第四节的链路断点 |

逐字稿是纯口语、整段无换行，直接读会很痛苦。先按标点切成 240-260 字/行的临时文件，再读（方法见 `analysis-playbook.md`）。
