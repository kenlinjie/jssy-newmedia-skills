# 踩坑清单（都是实际踩过的）

按「会直接导致交付翻车」排序。改代码、写情报、部署前扫一遍。

## 一、链接与站点

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 子页面不带 `?sharecode=<码>` | WorkBuddy 托管站点报「链接不完整」，用户打不开 | 所有链接由脚本自动附加；手写链接一律补 `?sharecode=<分享码>`（码存 `share/sharecode.txt`） |
| `scan_daily()` 只认 `.html` | 只生成 `.md` 的日期，站点「每日汇总」区块永远空白（**曾空了一个多月**） | 必须跑 `daily_intel.py` 出 `.html`；`digest.py` 也会出 html，别只留 md |
| 部署 `domainPrefix` 两边不一致 | 主任务与兜底/情报任务写了两个前缀，报告可能被重新部署到另一个域名 | 所有任务统一用 `<站点域名前缀>`；根地址固定 `<报告站根地址>` |
| `share/site` vs `share/online` 搞混 | 手动改了镜像，下次 build 被覆盖 | `site` 是 `publish_prep.py` 唯一生成源；`online` 是每次 build 自动整目录复制的镜像，部署用 `site` |
| 拆开跑 `sync_all.py` 三步 | 看板里的链接还是上一轮的旧链接 | 永远 `python sync_all.py`，不要单独调 `build_index` 后再调 `publish_prep` |

## 二、数据口径

| 坑 | 后果 | 正确做法 |
|---|---|---|
| `viewers.csv` 用 `split(',')[-1]` 取峰值 | 末列是**标题**，结果全是 0 | 第 2 列 = 在线人数，**第 4 列 = 累计观看**，末列 = 标题；用 `csv` 模块按列索引读 |
| 只读 `viewers.csv` 的 max 值 | 分不清真实起量还是数据抖动 | 打印 max 那一行的**时间**，看是否连续几分钟真实拉升 |
| ASR 误读数字 | 情报里出现 616 / 718 / 818 三个"淮中 600+ 人数" | 所有关键数字写进情报前 grep 回原文抽检，抽不准就写「口径存疑」 |
| 混用「达线」和「录取」 | 把口径差异误判成造假 | 引用时保留原词，两家对不上就并列写清楚 |
| 逐字稿只有最后一段（如 99 分钟只覆盖 21 分钟） | 复盘里把未覆盖时段当成"没讲" | 正文明确标注「该时段话术未获取」并说明覆盖率 |
| 空录音场次（1.5KB、只有 1 行） | 被当成有效场次算进 KPI | 盘点时剔掉 |

## 三、转写与报告

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 有 flac 没 `transcript.txt` | 报告「话术/内容要点」显示"未检测" | `python asr.py` 单段试，再 `recover_asr.py` 批量补，补完重跑 `report.py` |
| 只补了纯文本 `transcript.txt` | 报告仍显示"未检测" | `report.py` 提取话术依赖**带时间戳的 `transcript.srt`**，纯文本不够 |
| ASR 单消费者线程 | 若干号晚间撞场，报告排队延迟几分钟 | **不是错误**，别重启监控；等就行 |
| `config.json` 的 `max_recordings: 3` | 以为是并发上限，其实代码从不读取 | 并发录制实际无上限，别拿它做容量判断 |
| 改完 `monitor.py`/`asr.py`/`report.py` 直接重启 | 语法错误导致监控起不来 | 先 `python -m py_compile <文件>` |
| 有场次在录时重启监控 | 该场录音被截断、报告残缺 | 先 `cli.py status` 确认无「●直播录制中」；用 `idle_restart.py` 等空闲再重启 |

## 四、自动化

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 主任务在会话活跃时被推迟 | 已实际造成两次漏发 | **必须保留 #2 兜底任务**，靠 `email_sent.marker` 互斥，不要图省事关掉 |
| 没确认「已发送」就写 marker | 邮件其实没发出，但系统认为已发，永久漏发 | 先 `list_messages(dir=sent)` 确认，再写 marker；失败不写 |
| 为"确认一下"重发已发场次 | 同事收到重复邮件 | marker 存在即视为已发，跳过 |
| 启用已 PAUSED 的 #5 每日汇总推送 | 和在线情报页重复打扰 | 保持 PAUSED |
| `intel.json` 把 `kpis`/`chances` 写成对象 | 页面空白 | 二者都是**二元组数组** `[值, 标签]` / `[标题, 说明]` |

## 五、工具使用

| 坑 | 后果 | 正确做法 |
|---|---|---|
| bash 里 `python -c` 拼含反斜杠的 Windows 路径 | `SyntaxError` | 写成 `_tmp/*.py` 文件再执行 |
| Read 单次读超长切分稿 | 超 2 万 token 被截断 | 用 `offset` / `limit` 分两次读 |
| 逐字稿直接读 | 纯口语整段无换行，一行几万字，读不动 | 按标点切 240-260 字/行（见 `analysis-playbook.md`） |
| 日期用 UTC 算"昨天" | 早上 8 点前算错一天 | 一律 Asia/Shanghai |

## 六、前端（改站点样式时）

- 报告页缩略图 `object-fit:cover; max-height:400px`，看大图用 `contain`。**不能共用一个值**：共用会要么缩略图留白、要么大图被裁。
- `.shot span` 选择器要写 `.shot > span`，否则误伤内部元素。
- 「点击看大图」角标常显（`opacity:.72`），**不要改成 hover 才出现**——桌面截图/无鼠标设备发现不了。
- 看图层 `.lbx` 样式只写在报告页自己的 `<style>` 里，不属于 `site_pages.CSS`；首页/账号页的缩略图整卡已是链接，嵌套 `<a>` 不合法，不做看图功能。
- 抖音**不提供直播回放接口**，2026-10-30 之前只录了音频的场次无法补画面，站点显示「音频录制场次 · 画面自 10-30 起采集」是预期行为。

## 七、合规红线（勿动）

- 不开浏览器、不登录、代码内不写任何 Cookie（检测只走 streamget 内置机制）。
- 只录音频，不录视频、不抓弹幕。
- 在线人数/话术只取接口与逐字稿，拿不到记「未获取」，**绝不估算或编造**。
- 未经确认不向外部发任何消息。
- 邮件正文第六节「合规说明」为固定文案，不得删改。
