# 选版后的 Remotion 制作

只在用户明确选中视觉方案后读取。

## 建立隔离工程

优先运行：

```bash
python3 <skill-dir>/scripts/init_project.py \
  --root "/absolute/output/project" \
  --name "项目名" \
  --source "/absolute/source/video.mp4" \
  --platform "douyin" \
  --aspect "9:16"
```

脚本只记录源路径和哈希，不复制或改动原片。已有项目结构时不要重复初始化；补齐等价目录和清单即可。

把选版结果写入 `project.json`：方案编号、方向名、用户原话、确认时间、预览图和模板来源。后续版本沿用同一视觉语言；用户要求换方向时，返回选版门槛并产生新版本，不覆盖旧版。

## Remotion 工程

1. 在 `03-remotion/` 创建独立项目，保留 `package.json`、锁文件、配置、`src/`、`public/`、字体与静态素材。
2. 大媒体随机 seek 不稳定时，从原片流复制生成工程副本：

   ```bash
   ffmpeg -i source.mp4 -map 0 -c copy -movflags +faststart 03-remotion/public/source-fast.mp4
   ```

3. 先读取当前版本的 Remotion skills。用 `<Video>` 承载 A-roll，新增图形用命名 `<Sequence>` 对齐最终语音时间轴。
4. 对可变标题、颜色、数字和素材暴露清晰 props；不要把所有落点藏在不可编辑的循环里。每个语义落点在 Studio 时间线有可识别名称。
5. 中文、数字和关键排版由 Remotion 本地字体确定性渲染。生图/生成视频中的文字只作参考，正式画面不得依赖其拼写。

## A-roll 与版面

- 默认保持 A-roll 满屏或按源画面自然裁切。平台安全区只约束新增文字和素材；只有已批准效果图明确采用画中画、留白画布或缩进结构时，才改变 A-roll 尺寸。
- 按代表帧逐段判断脸、头发、嘴、眼镜、手势、产品和字幕位置。不要用一套固定坐标覆盖全片。
- 优先透明叠加和局部可读性处理。全屏信息页必须是已批准视觉语言中的明确语义节拍，不能用来逃避布局问题。
- 同一视频共用色彩、字体、间距和运动语气；不同信息任务可用不同机制。章节标记、数字、关系图和 CTA 不应全部变成同一种卡片。
- B-roll、音乐、音效、美颜、补字幕或重剪 A-roll 只在用户要求或已选方案明确包含时加入。

## 时间与声音

- 视觉出现时间由最终 A-roll/转写锁定；不要在仍会改变语音结构时批量放图形。
- 入口动作应落在关键词之前或同时，阅读完成后退出。避免无意义常驻和机械重复动画。
- 原人声为音频主轨。最后统一做 4 帧左右的裸露边缘淡入淡出和切口平滑；目标响度通常为 -16 至 -14 LUFS，真峰值不高于约 -1 dBTP。

## 版本与可复用性

- 正式 Composition 和安全区检查 Composition 分开；辅助线绝不进入正式输出。
- 输出使用 `v1`、`v2` 或用户命名版本，不覆盖已交付版本。
- `03-remotion/README.md` 写明 Composition ID、预览/渲染命令、源副本生成方式和可编辑参数。
- `project.json` 至少记录：源哈希、平台/比例、内容地图、选中方案、模板来源、字体/素材许可证、Composition ID、最终文件、QA 状态。

## 渲染前内部检查

从选中方案的所有主要落点各渲染一张 settled frame，并组成联系表。检查：

- 与已批准效果图的视觉语言一致；
- 人物、字幕和平台 UI 区没有被关键内容占用；
- 文本没有裁切、碰撞或单字孤悬；
- 没有未经批准的黑框、画中画、全屏卡片或风格漂移。

发现明显偏移时先修工程。若必须改变已批准方向，重新提交效果图并等待用户确认。
