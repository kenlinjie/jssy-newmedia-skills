# ego Lite 差旅报销填单

把老师这次真实出差的发票和行程，填进老师本人的报销系统。填完后能重新打开核对，金额和发票对得上，拿不准的地方已经问清或明确留下。

本文件是唯一正文，不依赖任何私人笔记、个人旧单或固定设备路径。各地流程可以不同：当前财务要求优先，当前页面用于确认实际字段和限制，旧单只作参考；它们都优先于这里提到的页面经验。

## 先确认做什么

- 本技能处理差旅报账单。页面实际是其他单据时，不因为字段相似就套用；先问老师是否换单据类型或改用其他流程。
- 只处理老师本人或明确获授权的账号、发票和行程。不要查看无关旧单、发票或其他人的报销信息。
- “帮我填单”包含必要的上传发票、关联发票、填写和存草稿，不包含提交、审批、付款或替老师向财务发消息。
- 默认只存草稿。只有老师明确说“提交”，并且能确定要提交哪张单，才执行提交。

## 检查浏览器和登录

需要浏览器时先读取 `ego-browser` 技能，运行下面的命令，并完整阅读它返回的当前版本指南：

```bash
ego-browser skill
```

命令不可用或没有接入时，引导老师从 [ego Lite 官网](https://www.egolite.ai/download)安装并按当前官方说明接入。技能文件存在，不等于浏览器和账号已经可用。

整个报销任务使用同一个 TaskSpace；登录交接、页面报错或等待老师回复后，继续接回原任务。不要关闭老师自己的标签页，也不要另开任务绕过问题。

先打开老师提供或已经打开的报销网站，再检查真实登录状态：

- 未登录、需要扫码、验证码、切号或授权时，按当前 ego Lite 指南把页面交给老师。一次只告诉老师当前要做的一步，例如：“请你在打开的官方页面扫码登录。密码和验证码不用发给我，登录好后跟我说一声。”
- 已登录也要核对可见的姓名、单位或组织。出现多个组织、报销主体或账号时，让老师选这次应该用哪一个，不凭上次经验猜。
- 不索取密码、验证码、Cookie 或 Token，不擅自退出账号、清理登录状态或切换浏览器配置。
- 打开首页或看到头像，不足以证明登录的是正确账号；还要能进入老师本人的报销页面。

## 准备材料，只问缺少的

先读老师已经提供的信息和文件，再把缺少的问题合并成 1–3 个简单问题。宿主有问答工具时实际发起提问，不让老师填技术字段，也不重复问已经明确的内容。

通常需要这些材料：

| 材料 | 要确定什么 |
| --- | --- |
| 本次发票 | 文件或文件夹在哪里；哪些属于这次报销；是否有打车行程单、车票或其他证明 |
| 真实行程 | 出差日期、出发地、目的地、实际消费日期、出差做什么 |
| 当地填法 | 同地区、同单位、同类单据的旧单或财务要求；几趟出差分开报还是合并报；要附哪些材料 |
| 本次身份 | 实际申请人、报销单位、收款信息；优先由系统本人账号带出并核对 |

可以这样问，按实际缺口取舍：

- “这次报哪几天、去哪几个地方？发票在哪个文件夹？”
- “有没有你们这里以前填过的同类差旅单？我只参考填法，不会照搬姓名、部门和银行卡。”
- “这趟出差主要做什么？我帮你写成一句简单的事由，你确认后再填。”
- “系统里这两个单位该选哪一个？”

找不到旧单、当地要求说不清、页面和旧单不一样时，直接告诉老师哪里不一样，问清再继续。不要拿另一个地区的旧单当依据，也不要把“以前都是这么填”当成本次规则。

## 第一步：只读看旧单

有旧单时，优先看同地区、同单位、同类且已提交或已完成的单，并记下旧单日期；草稿只能作为较弱的参考。先读后填，不修改旧单。旧单只能证明当时这样填过，不能证明规则现在没变。旧单过旧、日期不明，或与当前财务要求、页面提示冲突时，涉及分单、分类、补助和附件都要停下问清。

旧单只用来了解：

- 单据入口和类型；
- 一趟出差分几张单；
- 行程、费用分类、补助和附件怎么填；
- 事由的写法、支付方式和常见必填项。

以下内容必须重新从本次页面、票据或老师回答中确认，不能照抄：申请人、部门、成本中心、教学区域、业务板块、银行卡、金额、日期、城市、事由、补助、邮寄张数、发票和附件。

## 第二步：整理本次票据

在本地读取老师指定范围内的发票和证明，先列清每张票，再上传。至少核对：

- 发票或票据日期、实际消费日期、不含税金额、税额、价税合计和费用种类；报销金额采用哪个口径，按当前页面和当地要求确定；
- 车票的出发站、到达站、乘车日期；打车的行程和行程单；
- 属于哪一趟出差，是否重复、缺页、模糊或不是本次材料；
- 每趟的小计和全部合计。

票面看不出来的信息保持不确定，向老师指着具体票据问，不猜站名、城市或用途。实际出差日期与开票日期不同，两处都保留，不能用开票日期替代真实行程。

分单方式按当地旧单或财务要求执行；没有依据就问：“这几趟是分开报，还是合在一张单里？”不要固定套成“一趟一张”或“全部一张”。

## 第三步：上传并查验发票

使用当前页面实际提供的发票入口，例如“我的发票”“电子发票上传”。首次上传前，列明准备上传的文件，用大白话告诉老师：“这些发票传到系统后要先查验，有些单位查验后会锁定或占用发票。确认上传吗？”得到同意再传。页面另外出现“占用、锁定、不可撤销”等提示时，再次停下请老师确认，不把说明当成已经同意。

- 只上传本次确认过的文件。部分系统查验后会锁定票据；发现文件拿不准时，先停下问，不靠反复上传试结果。
- 等待每张票的实际结果，记录成功、失败、重复或信息缺失。只有符合当前系统要求且查验成功的票才关联进单子。
- 上传超时或页面报错后，先查发票池和已有草稿，确认实际结果，再补未完成部分；不要整批重传造成重复。
- 失败、重复、抬头不符或信息缺失的票单独列出，问老师是更换文件、补充信息，还是本次先不报。不要绕过查验。
- 查验后不能修改的票面信息，不承诺可以改。能在单据行程里补充的，按实际车票和老师确认填写；影响报销的先问财务要求。

## 第四步：填单并保存草稿

按当前页面填写，不把这里见过的字段名当作每个单位都相同。

1. **先核对人和单位。**新建差旅单后，检查实际申请人、报销单位、成本中心和单据类型。系统自动带出的内容也要看；不对或看不懂时问老师，不直接沿用。
2. **关联本次发票。**每张票只放进计划中的一张单，关联后核对张数和金额。不要把失败票或其他行程的票带进来。
3. **填真实行程。**按实际出差日期和城市填写。城市需要点选时就使用选择器，不反复用页面不接受的输入方式。
4. **处理日历差异。**有些系统会按开票日期自动放费用，未必等于实际消费日期。不能调整时不要硬拖；在允许的明细或备注中写清实际日期，并把差异告诉老师。影响当地报销口径时，先问清再继续。
5. **选费用分类。**从当前页面实际选项和当地要求中选择。餐费、车票、打车、住宿分别怎么归类，不因旧系统只有某几类就套用。
6. **写事由。**用老师确认过的真实事项写一两句白话，不编造培训、诊断、会议或接待内容。老师已有固定写法时，只借用句式，事实仍写本次。
7. **核对补助和其他字段。**补助、补贴、邮寄张数、业务板块、教学区域等按本次规则填写。旧单是 0，不代表这次也应填 0；不确定的必填项先问，不能用猜测值通过校验。
8. **准备附件。**按当地旧单或财务要求附费用明细、打车行程单等。需要明细表时，沿用当地空白模板的结构，只写本次数据，并注明开票日期与实际消费日期不同的项目。不多传无关材料。
9. **核对支付信息。**检查收款人、脱敏银行卡、金额和用途。收款信息不对时让老师在官方页面处理或确认，不在聊天里收集完整卡号。
10. **分段保存。**关键部分填完后保存草稿。保存报错或超时，先到草稿列表查实际结果，再决定补填还是重试，避免重复建单。

## 第五步：重新打开核对

保存成功提示不是验收结果。到“我的草稿”或当前系统对应入口，重新打开每张单；必要时刷新后再看。逐项核对：

- 单号、申请人、报销单位和单据类型；
- 出差日期、城市、事由和费用分类；
- 发票张数、每张金额、各单小计和全部合计；
- 补助、支付金额、收款人和脱敏账户；
- 附件能否看到，文件名是否属于本次；
- 之前拿不准的项目是否已经解决，或仍明确保留待确认。

分别核对纳入本单的有效票合计、未纳入票据及金额、补助或扣减、最终支付金额。它们口径不同，支付金额不必机械等于发票合计，但差额必须能由已确认的补助或扣减解释。对不上时先找具体差额，不为了对齐总额改票据或猜数。无法读回的单据标成“待核验”，不能报告已存好。

## 提交边界

老师只说“填好”“照着旧单填”时，最后交付草稿，不点提交。

老师明确要求提交时，先确认本次要提交的单号和范围，再按授权提交。以下任一情况存在都不得提交：仍有没决定怎么处理的发票、待确认必填项、解释不清的金额差额、申请人或报销单位未核对、收款信息未核对、草稿无法读回。老师授权提交后，如果单号范围、报销金额或收款信息发生变化，要重新说明并取得确认。

提交后重新打开或查看状态，只有页面实际显示已提交、审批中等明确状态，才报告提交结果。没有读到状态就照实说“已点击，但状态还没核实”。

## 跟老师怎么说

全程用大白话、短句，少讲系统术语。必须提到页面字段时，用引号保留原字段名，再补一句人话解释。

- 登录时一次只给一个动作；其他问题合并问，不问老师已经回答过的内容。
- 不说“配置核算主体”，改说“确认这次用哪个单位报销”。
- 不说“票据归集与关联”，改说“把查验通过的发票放进这张单”。
- 不逐个点按钮都汇报，只在登录、发票查验、草稿保存、需要老师决定和最终结果时反馈。
- 拿不准就具体问：“这张 11 月 6 日的车票没识别出出发站，票面上写的是哪个站？”不要只说“信息异常”。
- 没提交就明确说：“两张单都存成草稿了，没提交。”不要只说“报销完成了”。

## 异常时怎么停

- **登录或安全验证：**交给老师在官方页面完成，不绕过、不循环重试。
- **没有当地依据：**能只读整理的材料先整理；涉及分单、分类、补助或其他关键填法时停下问。
- **发票部分失败：**其他互不依赖的部分可以继续，但最终必须列明哪张没进单、金额差多少、下一步要老师做什么。
- **页面变化或操作受限：**说明实际卡在哪一步，保留已经保存的内容，不用连续点击或换入口强行试。
- **已有同行程草稿：**先核对是否为本任务所建，避免重复；是否续填、覆盖或删除旧草稿，按老师明确选择处理。

## 最终交付

用简洁表格或短清单告诉老师：

- 每张单的单号、行程、发票张数、金额和附件；
- 全部合计，以及和本地票据核对的结果；
- 当前是“已存草稿，未提交”还是已核实的其他状态；
- 仍需老师决定或补充的具体事项；
- 本地生成的明细表路径（有的话），以及结果页已留在 ego Lite 中（确实保留时才说）。

只要还有发票未处理、必填项未确认或单据无法读回，就只能报告部分完成，并给出下一步。最终回复不展示完整银行卡、身份证号、手机号、登录凭据或其他无关个人信息。
