# 小白 AI 环境配置向导

让已有本地 agent 的用户，完成所选软件的安装、登录、办公平台接入，以及 Obsidian 知识库的本地版本管理。已有 WorkBuddy、CodeBuddy 或其他能运行此 skill 的 agent 是前提，沿用它，不另建起步 AI 方案。

若用户提供的是本地解压目录，直接读取此文件和同目录的按需资料，不以 GitHub 可达、`git clone` 或在线安装本 skill 为前置条件。首次使用不要求已有 Git；Git 由下面的环境配置步骤安装。能读取本地 skill 与能下载软件是不同条件，下载受阻按 [官方渠道与代下载](references/downloads.md#github-不可达时) 处理。

## 选择路线

| 情况 | 本档安装的软件 | 所有档位都安装或配置 |
| --- | --- | --- |
| A：不能科学上网 | ego(lite) | Obsidian、Git、Obsidian Git 插件；钉钉／飞书／两者 |
| B：能科学上网，希望简单使用 | ChatGPT ＋ ego(lite) | 同上 |
| C：能科学上网，愿意折腾 Claude | ChatGPT ＋ ego(lite) ＋ Cindy ＋ Claude Code | 同上 |

Claude 默认指 Claude Code。若用户明确指 Claude 桌面版，按其指定调整并记录，避免把两种产品混为一项。不能科学上网但愿意折腾时，先完成 A，海外服务部分列出尚缺的访问条件。

## 开始时做什么

1. 只读检查当前电脑的系统、原生芯片架构、已安装软件及现有 agent 能力。**远程执行器的系统不是用户电脑的系统**；不能操作目标电脑时，转为针对目标电脑的逐步指导，不能声称已安装。
2. 已经知道的情况直接沿用。只问尚缺的：网络属于哪一档、是否愿意折腾 Claude、用钉钉还是飞书或都用。用宿主提供的提问工具；没有时用简短文字询问。
3. 检查是否已有 Obsidian 知识库。有则询问使用哪个；没有则建议在系统“文档”目录新建 `AI知识库`。确定目标后，才能写文件或初始化 Git。
4. 用一句话说明将安装的组合并开始。请求安装环境已授权对应下载和普通配置；登录、扫码、系统密码、企业审批由用户在官方界面完成。复用已有安装、账号和设置，避免重复安装、全局重配。

## 需要具备的能力

- 有目标电脑的本地命令／文件权限才能自动下载安装。缺少这些能力时，给用户当前步骤的官方下载入口和点击说明。
- 有实时联网查官方版本的能力；若本机上不了发布站，可由当前 agent 从可访问的官方渠道查询，区分“查到新版”与“目标电脑已下载”。
- 浏览器安装前先用 HTTP、官方 API 或现有工具获取下载资料；有可用的 ego(lite) 后优先用它处理网页。登录验证才请用户接管界面；不自行接管用户桌面。
- CLI、插件、MCP 的能力和权限以当前工具实际返回为准。安装了 ChatGPT 不代表已有 CLI、API 额度或办公平台连接。

## 执行顺序与按需资料

1. 先读 [官方下载与版本核验](references/downloads.md)，**每次执行重新查**所选产品的当前发布渠道、平台支持、最新版本和下载地址。
2. 只读目标系统的步骤：[Mac](references/macos.md) 或 [Windows](references/windows.md)。先安装本档软件和通用依赖，再逐项读回版本。不要为读取资料提前启动应用；需要初始设置时再打开。
3. 所有档位执行 [Obsidian 与 Git](references/obsidian-git.md)：打开指定知识库、启用 Git 插件，完成一次可核对的本地提交。远程备份是独立选项，不自动创建远程仓库或上传笔记。
4. 执行 [钉钉与飞书接入](references/workspace-connections.md)，只加载所选平台部分；两者都选则分别认证、分别验证。钉钉业务操作统一用 `dws`。
5. 用现有 agent 调用 `ego-browser`，读取一个用户网络可访问的公开页面的标题。A 档使用国内可访问的公开站点，不用海外站点测试。只读、无登录的测试即可。
6. B／C 档分别验证 ChatGPT 登录和一次回答；C 档还要验证 Cindy 中所选模型可回答、Claude Code 能启动并完成一次简短回答。复用用户已拥有的订阅或密钥，不因安装而自动购买。

## 始终获取新版

- **不保存固定版本号、旧安装包地址或上次的“最新版”作为本次结论。**只采用当次从官方页面、官方发布 API、包注册表或软件更新器取得的证据。
- 默认当前正式发布渠道；官方专有的 `stable`／`latest` 频道以当次文档为准，不能把 `latest` 自动当测试版，也不能把延迟的 `stable` 说成最新版。只有 Beta／Preview 可用时先说明，由用户选择是否使用。
- 支持系统／架构、安装文件格式、最低系统要求都要现场核对。缺少匹配产物时说明限制，不能装错包或静默退回旧版。
- 每项记录：查询时间、官方来源、目标版本／频道、实际安装版本、兼容性、使用验证结果。没有公开版本号时使用官方当前下载入口并保留应用内“已是最新”的核验结果。
- 提供了可选只读脚本 `scripts/resolve_latest.py`。有 Python 3.9+ 才运行；没有就直接查官方页面／API，不额外安装 Python。脚本只查发布元数据，**不会下载、安装、认证，也不证明目标电脑已经更新**。
- 查不到版本、下载失败、更新需重启、系统不支持时，该项保留“待核验／待重启／受阻”。保留已完成结果并继续互不依赖的部分，不能报告全部完成。

## 面向小白的沟通

每次只给当前需要用户处理的一步：在哪个软件、点哪个入口、会看到什么、完成后如何继续。命令由有权限的 agent 执行；确实要用户粘贴时，先说明如何打开对应终端。

凭据只在官方登录页、系统凭据管理器或宿主安全输入中处理；不索要聊天中的密码、验证码、Token，也不把凭据写进知识库、Git 或安装报告。安装范围内的普通操作继续执行，遇到真正缺少的选择或权限才询问。

再次运行时检查并补齐剩余步骤：不重复建库、不重置 Git 历史、不覆盖插件配置、不登出已可用账号。既有冲突、非本人权限或企业管理员审批受阻时，说明具体缺口和继续条件。

## 完成标准

交付一张简洁清单：所选档位与系统、每个软件的目标／实际版本、官方来源和核验时间、办公平台的认证及真实读取结果、知识库位置、Git 提交短哈希、Git 插件内可见的历史。选了两平台时必须有两份结果。

本地 Git 通过与远程同步通过分开写。远程未选择时写“未启用远程备份”，这不妨碍本地版本管理完成。远程已选择但没推送成功时只能报告该部分未完成。

用户选择自动提交／自动远程备份时，还要记录实际间隔与推送开关，并观察一次后续修改被定时提交／推送；只有手动通过不能宣称自动备份完成。知识库嵌在上级 Git 仓库中时，自动提交范围及整个分支历史的推送范围必须按 [专项说明](references/obsidian-git.md) 分别核对。

只有所选必需项都安装、版本核验通过、应用能启动、浏览器能被 agent 调用、所选办公平台能真实读取、Git 插件内能看到提交，才报告配置完成。附三句可直接使用的示例：让 agent 查指定办公文档、保存一条笔记、查看笔记历史。
