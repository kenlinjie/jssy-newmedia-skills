# 钉钉与飞书接入

接入是让执行任务的本地 agent 能调用工具读取用户授权的办公数据。安装办公客户端、网页登录成功、加了机器人、绑定 IM 消息入口，都不能单独证明这个能力已经接通。

先问使用钉钉、飞书还是两者。平台与账号已明确时直接沿用，两个平台分别记录版本、身份、组织和读取结果。不要发送测试消息或新建业务文档来验收。

## 通用准备

- 复用现有可用安装与登录，不为走教程先登出、删除凭据或重建应用。
- 如所选 CLI 需要 Node／npm，先读取当前官方要求并检查现有版本；缺少时按 [系统步骤](../SKILL.md#执行顺序与按需资料) 安装当前受支持 LTS。CLI 若支持官方独立二进制，可优先用它，减少依赖。
- 获取当前发布版本与安装方式，保留渠道来源。下载／安装只是准备，不是业务操作授权。
- OAuth 链接、扫码、系统密钥访问、企业审批由用户在官方页面完成。对话只给当前授权入口和操作说明，不要求用户粘贴密钥、设备码或完整认证输出。
- 多账号不能选列表第一项：复用明确的当前组织，否则请用户选择。安装报告只写用户能认出的账号／组织简称，不导出联系人列表或办公正文。
- 安装后确认当前 agent 进程能找到 CLI，必要时重载会话。检查官方随 CLI 提供的 skill 是否被当前宿主发现；未发现时按宿主现行路径接入所需 skill，不覆盖同名实体目录。此 skill 不依赖另一份必须预先存在的私有 skill。

## 钉钉：直接使用官方 CLI

国内入口：[钉钉 CLI 官方站](https://open.dingtalk.com/dingtalk-cli)。命令细节见[官方命令参考](https://open.dingtalk.com/dingtalk-dev/wiki)。

安装、更新、登录与官方技能接入均以官网当次说明为准，本项目不维护钉钉产品技能副本，也不把固定安装命令或旧版本作为当前事实。

复用现有安装与可用登录。核对当前 CLI 版本、本人身份和当前组织，再做一次用户授权范围内的最小只读业务读取。仅安装或登录成功，不代表文档、消息与表格均已获权；组织审批或权限受阻时如实记录具体缺口，继续其他独立部分。

授权、扫码与管理员审批在官方界面由用户完成，不索要聊天中的凭据，不发送测试消息或新建业务文档。官方技能、参数和权限按当前官网与准确命令的 Schema 核验；业务统一用 `dws`，CLI 无法完成时说明限制，不改用浏览器或其他连接器读写钉钉数据。

## 飞书：官方 lark-cli

来源：[larksuite/cli](https://github.com/larksuite/cli)、[飞书开放平台](https://open.feishu.cn/)。国内飞书与国际 Lark 的账号、应用和域名需要区分，按用户实际组织选择。

### 安装

在已确认当前 Node／npm 条件满足时，按当次官方 README 的 AI Agent 快速开始安装。当前入口为：

```bash
npx @larksuite/cli@latest install
```

安装器当前如何接入官方 skills 以实时文档和输出为准。核对 `lark-cli` 的实际版本与路径；不要把 npx 外层包的版本直接当成已安装二进制的版本。Windows 若仅脚本扩展名被策略阻止，可以使用已安装 Node 的 `npx.cmd`。

### 配置应用和登录

先检查当前配置与认证是否可用：

```bash
lark-cli auth status
```

没有应用配置时，依据当前官方说明引导官方应用配置；确需新建、用户选择了官方引导流程时，当前 AI Agent 入口为：

```bash
lark-cli config init --new
```

该流程在后台运行时，把它返回的官方授权网址交给用户完成。已有企业应用或配置直接复用，不无条件 `--new` 创建重复应用。需要 App Secret 时通过官方安全界面／CLI 交互输入，不让用户发在聊天中。

然后按用户实际需求选择授权范围，官方推荐流程当前为：

```bash
lark-cli auth login --recommend
lark-cli auth status
```

推荐范围以官方页面展示为准，不能把 `--recommend` 说成只读权限。用户在页面检查并选择；仅验证一个功能时可按当前文档使用对应的 domain／scope，日后需要其他功能再授权。

### 真实读取与结果

当前官方 README 给出的只读示例之一是：

```bash
lark-cli calendar calendars list
```

先核对当前命令和所需权限；有权限才读取。用户已指定文档时，使用当前官方文档工具读取该文档标题或首段，减少无关数据。返回成功但列表为空可以说明 API 调用通过、当前无数据；不虚构日程或文档。

`auth status` 成功而业务读取失败时，按实际原因区分缺 scope、应用未发布、管理员审核、目标内容无权限或租户错误。不能宣称“已全面接入”。需要用户／管理员处理的给出准确步骤，继续其他独立部分。

## 完成清单

每个平台记录：CLI 版本、当前选用身份／组织、认证状态、实际读取的能力、成功／空结果／缺权限、用户下一步。两平台之一受阻时保留另一平台的结果，不整体重装或重授权。

默认不测试“从钉钉／飞书给 agent 发消息”的机器人入口。用户明确要这种入口时，说明它是额外配置，按当前宿主的官方集成流程处理；不能把消息通道与办公数据读取混为一件事。
