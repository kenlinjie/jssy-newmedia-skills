# 团队通用日报 skill（daily-report-universal）

**一个包、自动认人。** 全体成员共用这一份 skill；每人首次使用时，由其 agent 读取本人钉钉历史日报，自动生成专属「个人画像」与本地配置。此后，这个包对这个人来说就是"他自己的日报助手"。

- 分发：整包复制给每个成员，各自初始化，互不影响。
- 升级：改进方法论只改这一份 `SKILL.md`，所有人下次使用自动受益。
- 个性化：与个人有关的一切只进 `local-config.md`，不进本文件。

本目录两个文件：

- `SKILL.md`：通用本体，可分发，不含任何个人信息。
- `local-config.md`：个人配置与画像。首次使用自动生成；**分发时必须保持空白模板，不要带已初始化的画像转发他人**。

## 触发 / 不触发

两类触发：

- **初始化（自动认人）**：用户说「初始化 / 初始化我的日报 skill / 根据我的钉钉日报生成我的日报 / 认人」。
- **日常使用**：「写日报 / 今天的日报 / 当天工作日报 / 补某天日报 / 周五日报（带周维度）」。

不触发：写周报 / 月报 / 季度总结；只读历史日报、看统计、口头复盘；纯数据分析出报告。周五日报仍是日报，只是反思带周维度，别写成周报式条块汇报。

## 开始前：读配置

共享项目只维护空白的 `local-config.example.md`。在本项目中调用时，将个人配置和历史样本放到使用者指定的项目外私有目录，按该路径读取；不要在共享项目中生成或保存个人画像。技能已安装到使用者自己的技能目录时，可从样例创建该安装目录下的 `local-config.md`，已有配置不覆盖。

每次运行第一步：读取会话已确定的项目外个人配置；独立安装时默认读安装目录中的 `local-config.md`。尚未确定配置位置时，先采用使用者自己的私有目录，不写进共享项目。

- 已初始化（不含 `〈待填写〉`）→ 按本 skill 执行。
- 未初始化，或用户明确要求重新初始化 → **进入「初始化：自动认人」**。用户若坚持先要草稿，只能给草稿、不落库。

## 初始化：自动认人

核心机制：**不问一堆问题，先读他本人的钉钉历史日报，从日报里把人"认出来"**。全程只读，绝不写回钉钉。

### 第一步：获取历史日报（按优先级回退）

1. **钉钉 CLI（首选）**——只读拉取「本人发出的日志」。按当前环境实际可用的方式调用，本项目使用：
   - **`dws`（钉钉全产品能力，WorkBuddy / Codex / CC 等已接入钉钉的环境通用）**：`dws report template list --format json` 定日报模板 → `dws report outbox list --cursor 0 --size 20 --format json` 拉「我发出」的日志列表 → 对每篇执行 `dws report entry get --report-id <id> --format json` 取完整正文。注意单次查询时间跨度上限 20 天，拉历史全量要按不超过 20 天的窗口用 `--start` 向前滚动查询；
   - 钉钉业务只使用 `dws`；CLI 无法完成时说明限制，转用用户提供的本地导出，不自行换连接器；
   - 工具名以环境实际暴露的为准；登录本人账号、具备「查询本人发出日志」能力即可。
2. **本地历史日报文件**：用户已导出或粘贴过的，直接用。
3. **手动提供**：以上都没有 → 请用户把钉钉日报导出或粘贴给 agent，只要「日期 + 正文」即可；或退化为问答式最小配置。

拉取策略与铁律：

- 先定模板：从「我发出」的日志里统计最常用的日报模板（通常一个主模板，如「XX部日报」「工作日报」）；**深度画像默认拉全量**（通常几十篇，至少近 60 篇或全部可见）。
- 逐篇取详情时**分批拉、边拉边存**，防止中断丢进度，并向用户汇报进度。
- **全程只读**：绝不调用创建 / 修改 / 提交日志的能力，绝不写回钉钉。
- 拉取到的历史日报统一存为**「历史日报原始记录」**文件（含日期、模板名、正文，按时间倒序），存放位置写进配置。一次存档，此后日常生成直接读它，不用重新拉钉钉。

### 第二步：深度画像（分析全部历史日报，产出 7 项）

1. **日报模板与结构**：标题、字段块及顺序（如 今日工作内容 / 工作反思与感悟 / 明日工作计划）、编号与排版习惯；数据以结构化字段块返回时（字段名 + 顺序），直接用它作为结构依据，不要猜。
2. **固定事项**：几乎每篇都出现的工作条目，如「数据监测复盘」。
3. **工作主线**：反复出现的工作主题及大致频次。
4. **阶段变化**：工作重心在时间上的演变，早期做什么、最近做什么。
5. **复盘维度与叙述方式**：内容按什么维度组织（项目 / 区域 / 学校 / 客户…）、习惯分条还是成段。
6. **表达与格式特征**：口吻、句子粒度、常用表达、数字与日期格式习惯、称呼习惯。
7. **数据习惯**：日报里常出现的数据字段，这决定可用数据源与取数方向；从不出现的字段是隐性红线；既有的缺失处理习惯。

### 第三步：确认与写入

- 用大白话给用户讲一遍画像，例如"你的日报基本围绕 A、B、C 三块，几乎每篇都有 D；按 E 方式组织；常用数据有 F；口吻偏 G"，再附详细画像供核对；**别直接甩表格给使用者**。
- 补问少数日报里推不出的信息：① 怎么称呼你 ② 工作素材来源，你每天做的事记录在哪 ③ 数据从哪来、怎么取，日报没有数据可留空 ④ 日报存到哪个目录、是否需要索引文件 ⑤ 有什么写作禁忌。
- 用户确认后把画像与各项配置写入 `local-config.md`，初始化完成，并告诉他："以后说'写日报'就行。"
- 样本不足（少于 10 篇）→ 说明情况，降级为「轻画像 + 问答补充」，并在画像里注明样本量。

## 硬门禁（三条，任何情况不破）

1. **真实数据**：日报必须有真实数据或用户提供的事实。来源优先级：① 用户当场提供 → 直接用；② 没提供 → 从配置的数据源读取，一律只读；③ 都没有 → **停下索要**，说明当前没有数据来源，请用户提供，**绝不编造**。缺失的数据不补位：没报的字段就不写，不按 0 补齐，不写负面找补或预测式解读。
2. **工作归属**：只写用户提供、确认、或能从素材明确归属于用户的工作。agent 自己的取数、搜索、核对、生成、验证过程（如「拉取数据」「核对记录」「写入成功」）**不算用户的工作**，不进日报正文，除非用户明确要求。
3. **先审后写**：生成后先在对话里给草稿，**用户明确确认后才落库**。默认不写任何外部系统（钉钉日志、OA 等）；用户明确要求时才走对应流程，并先给确认稿。

## 日常生成流程

1. 读配置：未初始化 → 先初始化。
2. 定日期：默认系统今天，**用命令取真实日期**（如 `date +%F`），不凭记忆；用户可指定补某天。判断是否周维度日（默认周五）。
3. 学最近样本：读历史日报原始记录最近 2–3 篇，对齐结构与口吻；已有画像的，以画像为准线。
4. 列当天工作：从配置的「工作素材来源」逐个列出当天做的事；**每件事先自己去素材里找内容**，找不到再问用户——别张口就问「你今天做了啥」；**不要因为素材为空就只模仿历史日报语气**编内容。
5. 取数据：按硬门禁第 1 条。
6. 生成 **Markdown 版 + 纯文字版**（见「输出两版」），先给用户审。
7. 用户确认后：Markdown 版写入输出目录（文件名默认 `YYYY-MM-DD日报.md`）；配置了索引文件则更新，未配置不建；不写外部系统。
8. 交付说明：日期、是否周维度版、数据来源、是否已落库。

## 日报结构（默认模板，初始化后用个人画像校准）

```markdown
---
tags:
  - 日报
created: YYYY-MM-DD
status: 已整理
source: 手动沉淀
---

# YYYY-MM-DD 日报

## 今日工作内容

1、（高度概括的动作，3–4 条，各条之间空行隔开）

## 工作反思与感悟

### 数据复盘：

（按配置的复盘维度成段叙述）

## 明日工作计划

（可选，有内容才写）
```

- **初始化完成后，结构以个人画像推导的结果为准**，覆盖本默认模板；字段块、顺序、编号习惯都可以不同。
- 「今日工作内容」：用 `1、2、3、` 中文编号，**各条之间空行隔开**；高度概括，不堆数据；固定事项默认放第一项。
- 「工作反思与感悟」分两块写：
  - **复盘块**：按配置维度（项目 / 业务线 / 区域等）**成段叙述**，每段挑 2–3 个有代表性的对象，点名 + 带数据 + 一句判断 + 下一步；**严禁**逐对象流水账 bullet 罗列；段末给后续重点观察项。无内容的小维度弱化为 2–3 句，不与其它维度等量铺开。
  - **工作块**：当天其它工作各成一段，一两句说清「做了什么 + 给谁用 / 解决什么」；写结论与用途，不铺过程；不夸大工作体量。

## 输出两版（默认都给）

- **Markdown 版**：带 frontmatter、`#` 标题、`**加粗**`、`---` 分隔——用于落库。
- **纯文字版**：无 frontmatter、无 `#` 标题号、无 `**` 加粗、无代码块包裹、无 `---` 分隔线；小标题用普通文字行，正文纯段落——方便整段复制进钉钉日志 / OA / IM。
- 两版文字一致，只差排版标记；落库永远用 Markdown 版。
- 配置中关闭纯文字版则只出 Markdown 版。

## 审稿与落库

1. 两版草稿先在对话里给出，请用户审。
2. 用户提修改 → 改到满意。**用户把修改后的定稿贴回并要求「学习 / 沉淀 / 更新」时：定稿是正文权威稿**——只做 Markdown 结构化与归档，不擅自恢复用户删掉的限定词、生成过程说明，也不新增工作事项。
3. 落库：写文件 + 更新索引（如配置）。
4. 定稿中体现的新红线、固定事项变化 → 写进 `local-config.md` 的「学习记录」，下次生成自动生效。

## 写作红线

**内置默认红线**（每次写完自检）：

- **不自嗨**：不堆「最亮眼 / 天花板 / 革命性 / 全程高能」等夸张评价；好就说好在哪、用数字撑。
- **不写比较评价**：不写「最好 / 绝对主力 / 最稳」这类横向比较词，直接描述事实和数据。
- **剥 AI 味总结壳**（必须过一遍）：
  - 「输出 X 作为 Y 范本」「作为…处置范本」→ 删；
  - 「整理…关注三件事」→ 直接进内容，不铺垫；
  - 「沿用昨天给到的方案」→ 直接列方案；
  - 段间导航「见下方」→ 删，靠顺序自然承接；
  - 主语冗余（如每句都带「团队」）→ 能省就省。
- **如实报数，不找补**：数据低就报数，不写预测式解读或负面找补。
- **不空泛套话，也别过度口语**：少用「拉满 / 一波带走」这类随意词；自然书面、半正式。
- **视角一致**：按配置的角色视角写，不跳出角色口吻，不写把自己摘出去的旁观语。

**自定义红线**（配置的「写作红线」区，逐条叠加）：不写的字段直接不出现；人名按配置处理；数字格式按配置统一，如日期用 `6.22-6.23` 不用 `6/22~6/23`。若个人画像的「数据习惯」里发现隐性红线，也一并按红线处理。

## 周维度分支（可配置）

配置启用且命中触发日（默认周五）时：

- 「本周」范围按配置定义，常用「上周五 ~ 本周四」（假设周五发布、当天数据来不及汇总）；
- 「工作反思与感悟」含本周小结：整体趋势 + 各维度表现 + 后续观察项；
- 仍是日报口吻，**不堆成周报式分块汇报**。

## 验收清单

- 初始化场景：画像 7 项齐全、已向用户讲清并确认；历史日报已存档；`local-config.md` 已写入、无 `〈待填写〉` 残留。
- 日常场景：配置已读取；已学最近样本；数据真实，无编造、无按 0 补齐、无找补。
- 复盘成段、点名带数；当天非数据工作都有对应段落，无遗漏。
- 红线自检通过（默认 + 自定义）。
- 已产出 Markdown + 纯文字两版且文字一致；落库前已先给用户审；落库后文件名、索引正确。
- 未写外部系统；交付说明含日期、数据来源、落库状态。
- 用户已给定稿时：正文与定稿一致，未回填被删内容。

## 异常与回退

- 钉钉 CLI 不可用（未安装 / 未登录 / 未授权）→ 如实说明，给两条路：先配置连接，或把钉钉日报导出粘贴给 agent；**绝不假装读到**。
- 无数据 → 停，索要，绝不编造。
- 数据源不可用 → 如实说明，不假装读到。
- 素材找不到 → 先全库 / 全目录搜一次，仍无再问用户。
- 历史日报样本不足 10 篇 → 轻画像 + 问答补充，画像注明样本量。
- 配置损坏 / 为空 → 重新初始化。
- 用户要求写外部系统（钉钉日志等）→ 才走对应流程，先给确认稿。

## 团队分发与维护

- **分发**：把本目录整包发给成员，保持 `local-config.md` 为空白模板。成员各自初始化，画像互不可见、互不影响。
- **不要**把已完成初始化的 `local-config.md` 转发给他人——里面是个人画像。
- **升级**：改进本 skill 只改 `SKILL.md`；成员的 `local-config.md` 不动，升级自动继承。
- **成员更换**：让对方重新初始化覆盖配置即可。
- 每次真实执行后暴露的新断点、字段、异常，补进本文件对应小节，优先补硬门禁与异常回退。
